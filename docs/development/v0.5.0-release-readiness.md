# v0.5.0 release candidate readiness

Prepared November 20, 2026. This is validation evidence and proposed release notes,
not an announcement of a published release. No tag or release was created.

**Status: READY FOR MANUAL ACCEPTANCE.** No known P0/P1 blocker remains in the
validated paths. Browser acceptance and a fresh installer/supervisor smoke run are
still required before release approval.

## Scope and audit

Commits 01–08 share the existing Pipeline IR, compiler dispatch, Studio draft and
Run lifecycle. The release integrates temporal features, generalized expressions,
selective/group-wise imputation, declarative cleaning and training-row selection,
numeric/categorical engineering, IQR treatment, variance selection, lineage and
model schema guards. Binary classification, multiclass and regression remain the
only supported tasks. There is no new migration, estimator or execution service.

The audit found stale public version/documentation references (P2) and regression
tests still assuming unwrapped preprocessing and pre-contract source plans (P2).
The full suite also exposed a fitted-state compatibility defect (P2): a Pipeline
prefix containing only `RawInputs` was rejected by scikit-learn as unfitted.
The guard now records standard input names/count on successful fit, matching other
stateless runtimes. Its raw-value projection and cleaning behavior are unchanged.
Historical golden files remain byte-for-byte unchanged: golden helpers now omit
the optional contract just as historical frozen execution plans did. Current-plan
tests still inspect actual train-only imputer/scaler/category statistics through
the schema guard and validate generated execution, metrics and predictions.

Next.js 16.4.1 also had moderate published advisories. Next.js and its matching
ESLint configuration are patched to 16.4.6; the production dependency audit is clean.
No affected application path was demonstrated to be exploitable. Development-only
dependency advisories are not a claim that the complete dependency tree is clean.

## Cross-feature evidence

`backend/tests/test_release_v05.py` adds three synthetic API journeys, one per task:

- Create a Project, upload/verify source semantics and obtain full-source EDA.
- Normalize/convert missing income values, fill UTC datetimes, filter training
  rows and deduplicate; derive temporal and arithmetic features.
- Fit group-wise imputation, stateless-to-fitted engineering, category grouping,
  IQR treatment and post-branch variance selection.
- Save/reload IR, inspect configuration-only preview, admit a real Run, read its
  frozen results and historical source, and independently execute that source.
- Load both complete models in a fresh interpreter that blocks backend imports.
  Check training-only fallback/fences, feature mask/order and equivalent predictions.
- Predict raw rows with missing values, an unseen group, extra/intermediate-name
  columns and duplicates. Preserve row count/order, reuse fitted state and reject
  missing required inputs. Preserve managed source and historical generated bytes.

Existing focused suites cover rejected dependency/stage/target references, fitted
chaining restrictions, empty variance selections, draft undo/redo, explicit reverts,
stale EDA handoffs, feature removal, task metrics and historical source goldens.
The release test complements these checks rather than duplicating each unit case.

Static resource review confirms the existing 20-row Studio/temporal previews,
20-column profile pages, 12-column correlations and 200-point regression scatter.
Profiling retains its configured source-size check. No new graph library, full
prepared-data profiling pass or background service is introduced. These bounds
do not establish a large-dataset memory or latency guarantee.

### Environment and limitations

Validation uses Windows 11, Python 3.14.2, Node 24.13.0/npm 11.6.2 and Rust 1.99.1.
Python/frontend package versions remain independently versioned at 0.2.0; the
public release and CLI identity are 0.5.0. Schema/generator/result identifiers and
historical migrations are preserved.

A running Node process locked the checkout's SWC native module during `npm ci`.
Patched frontend gates therefore run in an ignored clean copy under
`cli/target/v05-frontend-validation/frontend`, using the same source and lockfile.
No existing user process was stopped. The in-use native module was moved to
ignored CLI build storage and the checkout's clean `npm ci` subsequently succeeded
with Next.js 16.4.6. Restart/rebuild before manual acceptance so that an old process
cannot continue serving the previous Next build.
CLI unit/static/release-build checks do not replace a new installer/supervisor
smoke test. Cross-platform installation and browser acceptance remain manual.

The workbench is a trusted local-user application, not a hostile-code sandbox.
Joblib artifacts must be trusted. Semantic leakage cannot be inferred from column
names or structurally valid expressions. No performance benchmark or cross-platform
certification is implied by small deterministic integration fixtures.

## Manual acceptance

1. Stop your existing frontend normally, run `npm ci`, then start the documented
   two-server application using a backed-up local workspace.
2. Reopen an existing Project/Run and verify immutable historical Code/results.
3. For each task, upload a synthetic CSV, select the target and inspect source EDA.
4. Enter Studio through a revision-bound EDA action; keep an unsaved step, undo,
   redo, edit/remove a producer with consumers, and explicitly revert a branch.
5. Combine cleaning, temporal/derived features, group imputation, engineering,
   outlier treatment and variance selection. Check lineage and preview disclaimers.
6. Save, reload, configure Train and execute. Check task-specific Evaluate, Runs,
   historical Code and conservative comparisons.
7. Try invalid parameters, a broken dependency and missing required inference
   inputs; confirm actionable errors without silently discarding the draft.
8. Check narrow/wide Studio layouts and menus using the existing design system.
9. Verify the real CLI install/start/status/stop flow in a disposable workspace
   with free ports; verify both independent servers stop cleanly.

## Proposed release notes

**ML Studio v0.5.0 — Advanced Preprocessing**

- Table-first Data Preparation Studio with Applied Steps, explicit save/revert,
  undo/redo and actionable source EDA handoffs.
- Temporal and generalized row-wise features; selective/group-wise imputation;
  cleaning, validation, training-only filtering and deduplication.
- Numeric/categorical transformations, fitted IQR treatment and variance selection.
- Computed lineage, dependency/stage validation and portable raw/fitted model
  schema guards across generated Python and saved inference.
- Integration coverage for all three tasks, deterministic source/parity checks
  and standalone raw-input inference; patched Next.js production dependencies.

Compatibility: historical IR, Runs, source and older models are retained. New
optional extensions use existing JSON storage; no migration is added in this
release integration. Upgrade from an existing checkout with the documented backend
installation/migration commands and `npm ci`; rebuild the frontend and CLI. Back up
your workspace first. Previously frozen Runs are never regenerated.

Known limits: source EDA is not prepared-data EDA; previews do not fit statistics;
fitted-output transformation graphs and drag-reordering remain unsupported. No new
algorithm, automatic recommendation, cloud service, collaboration or dataset
format is included. Installer/signing/publication and GitHub required-check state
must be verified by the maintainer separately.
