# Code Mode Phase 2A: Python execution

This phase extends the Phase 1 single-file Monaco editor. It adds managed Python
execution and captured output inside Code Mode, not a shell, file explorer or
multi-language IDE. Visual Pipeline IR, visual Run protocols and MLflow remain
unchanged. Evaluation adapters belong to Phase 2C.

## Enable trusted local execution

Stop the backend, back up the workspace, and run `python -m alembic upgrade head`
from the backend environment. Migration `0008_code_runs` creates the independent
`code_runs` table; it does not rebuild existing tables. Downgrade is refused.

Set `MLSTUDIO_CODE_EXECUTION_ENABLED=true` and restart the backend bound to
`127.0.0.1`. Execution defaults to disabled. `MLSTUDIO_CODE_PYTHON_EXECUTABLE` may
select an absolute interpreter path; otherwise the backend's interpreter is used.
Existing timeout, per-stream log-byte and termination-grace settings are reused.
Run APIs reject non-loopback peers/Hosts and non-local or unapproved browser Origins.
These checks are not authentication, OS containment or a security sandbox.

Run only trusted Python. It has the local user's filesystem/process privileges;
path validation and isolated working copies do not prevent deliberate escape or
modification of other accessible data. There is no memory/disk quota, dependency
installation, Docker sandbox or remote execution. No new dependency was added.
Only the single entrypoint and originating managed Dataset are declared inputs;
arbitrary external files, network inputs and additional packages are not frozen.

## Run and inspect

Run atomically persists the editor text with its draft revision, creates an
immutable CodeSnapshot and a PENDING Code Run, then starts Python with an argument
array and `shell=False`. Each Run gets an isolated `main.py` execution copy. Later
draft edits cannot change that copy or the source retained in SQLite/snapshot.
The toolbar shows Run/Stop; execution and historical detail stay inside Code Mode.
Editing may continue while the frozen copy runs. Draft exit and Project deletion
are blocked until execution finishes. Saving a draft/snapshot alone never executes.

The managed interpreter receives `--dataset`, `--result` and `--model` when an
originating Dataset exists, matching generated Python's CLI. Custom argument
parsers must accept these options. Dataset identity/fingerprint comes from the
preserved draft binding, not the active visual configuration; managed CSV bytes
are verified and referenced without making another large Dataset copy.

Code Runs use the visual executor's shared workspace lease, process launch,
identity-checked tree cleanup and bounded capture helpers. Only one workspace
execution is admitted at a time; duplicate request IDs resolve their original Run.
Capture flushes live output for Code Runs without changing the visual default.
The UI polls sequentially at one-second intervals and shows the latest 64 KiB of
each stream. Raw bounded logs remain artifacts and may contain sensitive data.

Cancellation and shutdown terminate the owned process tree, wait for the grace
period, then force termination where supported. Known descendants are tracked and
cleaned up even if their parent exits. This is best-effort process management,
not containment of deliberately detached/unobservable children. Unconfirmed cleanup
blocks capacity rather than claiming completion. Restart recovery uses recorded
birth times and exact unique argv; interrupted executions fail, never resume.

Statuses are PENDING, RUNNING, COMPLETED, FAILED and CANCELLED. Exit code, UTC times,
elapsed duration, configuration, source SHA-256 and bounded logs remain inspectable.
COMPLETED means Python exited zero, not that ML outputs have been validated. Source
and finalized log integrity are checked on reads; missing/corrupt evidence is not
silently regenerated. Custom interpreter library versions are not probed; only the
backend interpreter's library versions are recorded when it is the selected Python.

## API and artifact contract

Under `/api/v1/projects/{project_id}/code-runs`:

- `POST`: revision-guarded source/draft/request UUID admission; returns 202 with Run
  and saved draft state. Conflicts return 409; execution-disabled requests get 403.
- `GET ?offset=N`: 20-item history, active Run and execution-enabled flag.
- `GET /{id}`: immutable source and execution details; cross-Project IDs return 404.
- `GET /{id}/logs`: bounded stdout/stderr tails and truncation indicators.
- `POST /{id}/cancel`: request cancellation of that owned managed execution.

Artifacts live at `projects/<project_id>/code-runs/<run_id>/`: `source.py`,
`execution.json`, `stdout.log`, `stderr.log`, and `workspace/main.py`. Generated
programs may write `workspace/result.json` and `workspace/model.joblib`. Failed
preparation can leave unpublished directories; there is no garbage collector.

[Phase 2B](v0.3-phase-2b-evaluation.md) now adds explicit structured-output validation,
immutable reporting artifacts and shared Evaluate presentation. Ordinary output
files are not metric contracts; console text is never parsed as evaluation evidence.

## Verification

Exactly four new focused tests cover success/exact source/output, failure/bounded
stderr, cancellation/tree cleanup/duplicate admission, and history independent of
later draft edits. All passed across development runs; only the failing live-output
case was rerun after investigation. The 29 relevant existing cases passed once.
Changed-file Ruff/format, frontend lint, typecheck and production build passed;
no full suite, browser QA, dependency audit or upgrade was performed. No commit.
