## Decisions

- Drafts are saved Python text, never runnable code or visual IR. Generated baseline
  and originating IR snapshot remain unchanged; edits are never parsed back to IR.
- Save updates mutable source. Save snapshot creates independent immutable code
  evidence, not a Run or result. Save snapshot and return is an atomic operation;
  discard is explicit and leaves the original visual recipe unchanged.
- Closing/navigation does not delete saved drafts. Exactly one active session per
  Project is persisted. Ended drafts/snapshots are separate from immutable Runs.
- Source size is bounded at 1 MiB UTF-8. No shell, terminal, code execution, import,
  filesystem browsing, new estimator or task is introduced.

## Verification and known limits

### User behavior

1. Configure a binary or regression experiment and open Code. **Edit Code** opens
   a confirmation; cancelling creates nothing. Entering regenerates and verifies
   the reviewed revision/source/plan hashes before persisting a draft.
2. Monaco provides Python highlighting, line numbers, native Undo/Redo and explicit
   Save draft. The indicator distinguishes unsaved edits from changes relative to
   the generated baseline. Reopen saved draft confirms replacement of unsaved text.
3. Close editor or navigate to another bench without ending the session. Saved
   drafts survive refresh/restart. Within the workspace the editor remains mounted
   to retain undo state. Tab recovery retains unsaved text across SPA navigation;
   matching revisions restore, while conflicting revisions remain inspect-only
   until explicitly discarded. Browser storage failure retains memory recovery and
   displays a save-before-refresh warning. SQLite remains authoritative saved state.
4. Data/Prepare/Train show a reentry warning while active. Continue returns to Code.
   Save code snapshot and return atomically preserves current text and archives the
   session. Discard resets its source to baseline and ends it without a snapshot.
   Neither mutates the original visual recipe. A later entry creates a fresh draft
   from the preserved visual configuration, never reverse-parses old Python.
5. Saved sessions/snapshots can be inspected read-only, with 20-item pagination.
   Existing Run source/results remain preserved. A snapshot is not a Run, result or
   execution. Explicit permanent Project deletion also deletes its drafts/snapshots.

### Persistence and API

Run migrations from the existing backend environment before starting the updated
application: `python -m alembic upgrade head`. Stop workers and make a consistent
workspace backup first. Migration `0007_code_drafts` creates only `code_drafts` and
`code_snapshots`; existing Project/Dataset/Run rows and artifacts are not rewritten.
The original objective migration rehearsal remains pinned to 0006. Current-head
compatibility checks explicitly permit only the two added tables and still compare
all historical rows, schema and file bytes. Downgrade is refused to avoid implicit
loss of manual work; restore a consistent pre-upgrade backup instead.

Under `/api/v1/projects/{project_id}/code-drafts`:

| Method / suffix | Purpose |
| --- | --- |
| `POST /` | Enter from reviewed generated hashes and Project revision; 201 |
| `GET /active` | Reopen active draft or null |
| `GET /?offset=N` | Session summaries, 20 per page |
| `GET /{id}` | Project-owned source/baseline/origin snapshot |
| `PATCH /{id}` | Revision-guarded source save |
| `POST /{id}/snapshots` | Save independent immutable source; return snapshot and updated draft atomically; 201 |
| `GET /{id}/snapshots?offset=N` | Snapshot summaries, 20 per page |
| `GET /{id}/snapshots/{snapshot_id}` | Exact saved snapshot text |
| `POST /{id}/exit` | Explicit discard or atomic snapshot-save/reentry |

Cross-Project resources return 404; stale edits/active-session visual writes return
409. Dataset upload/configuration, Pipeline save/reset and new visual Run admission
are guarded in backend services. Existing Run request-ID retries still resolve
their original Run. Draft creation waits until no active Run exists. Project
revision serializes session transitions against visual writes; independent draft
revisions prevent lost saves. No source is logged or reflected in validation errors.

### Editor assets and dependencies

Direct frontend additions are pinned `monaco-editor@0.57.0` and
`@monaco-editor/react@4.7.0`. Existing dependency versions remain unchanged.
`npm ci` runs `prepare-editor`; predev/prebuild repeat asset preparation. It bundles
Monaco ESM with only Python registration and serves the editor worker locally under
`/monaco/assets/`. No CDN, language server, terminal, shell or new backend dependency
is introduced. Generated assets/node_modules remain ignored.

Monaco pins and embeds an affected DOMPurify copy. A narrowly scoped npm override
pins 3.4.17, and preparation replaces the vendored ESM sanitizer with that installed
patched ESM source; merely overriding npm would not fix embedded bytes. The script
verifies the pinned version and preserves license notices. The prebuilt AMD editor
is not loaded. Existing Next.js/zod audit findings are not fixed through unrelated
dependency upgrades in this slice.

### Acceptance and limits

- No manual-code execution, terminal, filesystem browser, IR reverse parsing,
  new estimator/task, prediction storage or historical-source regeneration.
- A saved draft survives restart; unsaved recovery is a tab convenience, not a
  substitute for Save. With storage disabled a full browser restart loses unsaved
  memory buffers, so the application warns before leaving and asks users to save.
- Browser-native unload prompts and history cancellation vary by platform. The
  recovery buffer protects unsupported SPA traversal; stale text is never rebased.
- Chrome automation was unavailable because the computer-use tool could not verify
  the current browser URL. No visual acceptance is claimed. Manually check: cancel
  and confirm entry, highlight/line numbers/undo/redo, save/reload/reopen, close and
  return, Back/Forward recovery, snapshot/reentry, explicit discard and historical
  Run inspection, for both tasks.
