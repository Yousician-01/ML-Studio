## Review focus

Preserve binary defaults/range acceptance and generated bytes; avoid duplicate
catalogue validators; reject task/model mixing; count only observed targets; avoid
claiming known held-out target variation before a split; retain invalid/incomplete
editable intent; never derive preparation choices or fit/split during validation.

## Decisions

Regression negative alpha, nonfinite values, wrong types and unknown fields are
structural errors. Missing model/split and finite out-of-range split settings remain
saveable contextual issues. Binary out-of-range parameters retain their original
contextual behavior. The configuration contract must not imply execution support.
The catalogue is descriptive; regression adapter IDs reserve the later compiler
boundary and do not resolve Python imports or instantiate estimators.

## API and validation contract

The existing `GET/PATCH /api/v1/projects/{id}/pipeline` response now includes
`model_catalogue` and `configuration_ready`. Catalogue entries carry version
`model-catalog-v1`, stable ID/task/name, Pydantic-derived `parameter_schema` and
`defaults`, binary `contextual_constraints`, feature requirements and a closed
compiler adapter ID. Metadata is deterministic, detached and JSON-safe. No new
endpoint is needed. `model_defaults` retains exact classifier defaults and now
provides the two task-filtered regression defaults.

`configuration_ready` ignores only the explicit regression-execution blocker.
`prepare_valid` retains its preparation-only meaning; `code_generation_ready` and
`executable` remain false for regression. Parameter syntax errors return 422 with
field locations; incomplete model/split, finite invalid split ranges and feature
incompatibility can still be saved and corrected. API validation errors sanitize
nonfinite rejected inputs to JSON null in error details: Python's JSON decoder can
parse `1e309` as infinity, and FastAPI's original error encoder otherwise raises
while trying to return the finite-number validation error. Saved intent is untouched.

Split rounding uses `ceil(eligible * test_size)`, with only observed target values
eligible. At least two training and one test observations are required. A one-row
test population emits a non-blocking R2-unavailable warning. An entirely constant
observed target emits a separate non-blocking warning. For other populations no
claim of held-out target variation is made: no split, fit or metric calculation
occurs here. Actual R2 availability remains a later frozen-result concern.

Feature semantics/operation grammar remain shared. All five models require numeric,
complete prepared input, accept dense/sparse matrices and support only the existing
continuous/categorical/binary feature semantics. Non-numeric inputs need explicit
one-hot encoding; missing eligible feature values need explicit compatible
imputation; all-missing features must be excluded. No automatic transformations are
added. Dormant incompatible operations stay non-blocking. Stale regression recipes
retain their old model/split and report no counts from the replacement source.
