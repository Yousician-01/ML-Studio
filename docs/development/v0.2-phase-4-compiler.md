## Resolved plan and dispatch

`RegressionPlan` is version `0.2`, task `regression`, generator `mlstudio-python-v2`,
implementation `sklearn-local-v2`, CLI `cli-v1`, and result `mlstudio-result-v2`.
It freezes Dataset ID/fingerprint, exact source size and `csv-utf8-v1` parsing,
numeric target/physical/semantic interpretation, lossless float64 conversion and
missing-target exclusion; source-ordered feature operations; split fraction/seed;
typed estimator/adapter/parameters; Python and all five library versions; grouping,
matrix and metric policies. Rendering revalidates that plan without DB/source reads,
Project lookup, environment resolution, fit or split. Canonical sorted JSON binds
the entire plan to its SHA-256. Editable intent is copied during resolution.

`codegen/dispatch.py` explicitly loads/renders `0.1` or `0.2` plans and dispatches
known typed IR. Unknown/cross-task versions fail; no fallback upgrades old intent.
The v1 renderer and all embedded v1 source bytes remain unchanged. The v2 renderer
reuses fixed CSV/helper resources, safe literals and whitelisted preparation
constructors, embedding only the common I/O/environment helpers it needs. Emitted
source has no ML Studio imports and can run with the declared Python dependencies.

## Estimator implementation choices

- Linear Regression: explicit `fit_intercept`, `copy_X=true`, `tol=1e-6`, `n_jobs=1`,
  `positive=false`. Dense least squares and sparse LSQR behavior are provided by
  the pinned sklearn implementation, not an auto-selected Ridge solver.
- Ridge: explicit nonnegative finite `alpha` and `fit_intercept`, `solver="lsqr"`,
  `tol=1e-6`, `max_iter=10000`, `copy_X=true`, `positive=false`, `random_state=null`.
  LSQR accepts both supported dense and sparse matrices with an intercept. Direct
  dense/CSR checks against independently derived centered normal equations passed
  before freezing goldens; generated dense/sparse programs also passed.
- ColumnTransformer keeps one branch per source feature, `remainder="drop"`,
  `sparse_threshold=1.0`, `n_jobs=1`, `verbose=false`, explicit feature names. Existing
  imputation/scaling/one-hot constructors retain all their resolved v1 parameters.
  No automatic preprocessing, target imputation or stratification is introduced.

## Standalone workload and source identity

The unchanged bounded verifier hashes the exact source byte buffer that is then
parsed. Python/library versions and physical dtypes must match. Missing targets
are excluded; original numeric target values are checked before float64 conversion.
Booleans, unsupported objects, infinity and lossy integer conversions fail closed.
Constant and two-valued numeric targets remain valid.

The workload splits before fitting any preprocessing. It checks training/test
population minimums and all-missing training features, fits the complete Pipeline
on training data, predicts the test rows once, and writes that complete fitted
Pipeline with the existing atomic joblib writer. Source and output locations are
runtime details; paths must be distinct/new/absolute under the existing CLI policy.
No rows, predictions or scores are written into result metadata or logs.

The result records the executed file's SHA-256; controlled validation supplies the
independently recorded persisted source hash and checks equality. Tests compare the
file before/after execution. This is not signed authenticity, an adversarial live
file-mutation guarantee or a substitute for Phase 5's admission/artifact finalizer.
Failures return nonzero and a v2 failed document with fixed/sanitized stage messages.
Individual artifact writes are atomic; SQLite/filesystem publication is not claimed
to be one transaction, and no production publication is added here.

## Regression result protocol

`RegressionResult` is a strict, extra-field-forbidden success document containing:

- `schema_version="mlstudio-result-v2"`, `task="regression"`, `status="success"`.
- Frozen `dataset`, full `source` parsing contract, `generator`,
  `implementation_version`, `plan_sha256`, and `source_sha256`.
- Frozen estimator `model`, and `evaluation` containing target, split, ordered
  feature preparation and `sklearn-regression-v1` metric definitions.
- `population` source/eligible/training/test counts, `metrics` MAE/MSE/RMSE/R2,
  `r2_unavailable_reason`, and aggregate `test_target_constant` evidence.
- Python/library `versions`, and model declaration
  `{"model":{"kind":"complete_pipeline","filename":"model.joblib"}}` in `artifacts`.

`execution/result_dispatch.py` selects strictly from the expected frozen plan and
result protocol. It validates the full v1 expected-plan schema before delegating
to the unchanged v1 result validator, rejecting cross-task/unknown IR contracts.
V2 additionally
requires the expected generated-source hash; unknown, malformed or mismatched
protocols fail with `result_invalid`. It is not wired into the public executor.
Result reads are bounded, duplicate JSON keys/nonfinite constants are rejected,
and raw context is compared canonically to prevent Boolean/string coercion.

## Numerical policies and evidence limits

MAE/MSE/RMSE must be finite and nonnegative. RMSE must match `sqrt(MSE)` with
`rel_tol=1e-9`, `abs_tol=1e-12`. True zero losses are retained. R2 may be negative;
available values must be finite and at most one. With fewer than two test rows,
reason is `test_population_too_small` (takes priority); otherwise an exactly constant
test target uses `constant_test_target`. In those cases R2 is JSON null, never a
fabricated zero/one. Other nonfinite calculations fail the workload rather than
inventing another unavailability policy. No metric is rounded or clipped.

Population totals must match trusted expected source/eligible counts and seeded
split rounding, with two training rows and one test row. Availability must agree
with counts and the aggregate constant flag. Validation checks structure, frozen
context and internal consistency; without predictions it cannot independently
recompute losses/R2 or prove which held-out rows were used. Representative real
workloads are separately checked against independent sklearn calculations. Exact
source determinism does not promise bitwise model equality across hardware/builds.
