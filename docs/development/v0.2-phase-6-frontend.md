## API contracts and task-specific screens

Project creation sends explicit `ml_objective` with classification selected by
default; settings omit that immutable field from PATCH. Project list/header show
the actual task. Current Pipeline types discriminate binary IR 0.1 and regression
IR 0.2, sharing feature operations and the existing revision-guarded endpoints.
Catalogue descriptors carry backend defaults, parameter JSON schemas and contextual
constraints; no independent frontend model-default table remains. Code preview,
Run requests, polling, idempotent transport recovery and historical Code continue
through the existing clients. Opening Code does not execute a Run.

Data offers numeric dtype candidate hints only: backend validation still decides
finite/non-Boolean/lossless numeric eligibility. Constants/two-valued numbers are
allowed, observed/missing counts are shown, and missing targets are excluded.
Prepare reuses the same participation/operation editor, dormant intent, source
order, stale/reset behavior and immediate saves. Regression has no positive-class
control. Workspace passes its task explicitly to Explore; the regression surface
explains that full profiling is unavailable and links to actual source inspection
in Data without making the unavailable API request or inventing charts.

Train consumes catalogue names/defaults/parameter schemas for existing classifiers
and Linear/Ridge. It renders numeric alpha and Boolean fit-intercept controls;
regression split intent has no stratification field. Binary split editing retains
explicit false stratification. Raw editor strings remain local until explicit
Save. Metadata-driven parsing checks types/structural bounds; backend contextual
issues remain authoritative. All readiness issues are grouped exhaustively,
including target-scoped training blockers, constant/tiny-target R2 warnings and
ungrouped compatibility issues. Saved configuration validity, Code readiness and
reviewed-source/capacity-based Run admission remain distinct.

## Unsaved-change protection

Drafts are raw values plus Project revision and editing section, held in memory
and sessionStorage when available. They are not authoritative Pipeline state and
contain no Dataset rows. Same-revision drafts recover on return; older drafts
remain retained with a conflict warning, never silently rebased or submitted.
Model/split sections cannot overwrite each other's dirty draft. Save uses a
synchronous in-flight lock; failed saves retain input. Reset is explicit.

Document link capture prompts before same-tab navigation; Workspace refresh/settings
also consult the guard. `beforeunload` requests the browser's native protection
for dirty edits or pending saves. Cancelable browser traversals use the Navigation
API when present; otherwise retained drafts protect input after navigation.
Browsers determine unload/traversal cancellation and prompt wording. Storage-disabled
sessions retain in-memory drafts and unload protection but cannot guarantee recovery
after a permitted hard reload. Native dialogs/focus/navigation remain browser
acceptance items because automation is unavailable here.

## Historical results and comparison

Run result types discriminate result-v1 and regression result-v2. Shared metrics,
context and Run history show MAE/MSE/RMSE/R2 for regression, preserving true zero,
negative R2 and null-with-reason. No binary matrix/AUC/class controls or prediction
plots are displayed for regression. Training/test counts, frozen model/preparation/
split, tracking and artifact integrity remain inspectable. Nullable `result_error`
and unknown result/plan formats render warnings; unsupported frozen snapshot shapes
are not interpreted or mapped as supported feature arrays.

Comparison is the existing pure frontend policy; there is no backend comparison
endpoint or second metric source. Exactly two distinct successful owned Runs are
required. Cross-task comparisons are rejected. Deltas additionally require coherent
supported task/IR/plan/generator/result protocols, equal Dataset fingerprints,
target/source interpretation (typed class orientation for binary), split settings,
relevant library/implementation versions, held-out population, metric definitions
and verified artifacts/configuration. Models and preprocessing can differ and remain
visible as frozen context. Matching context does not independently prove held-out
row membership. Missing/nonfinite metric values have no delta; direction is labelled
without a ranking, winner, significance claim or prediction-level analysis.
